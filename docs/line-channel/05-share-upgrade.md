# Phase 7 — อัปเกรดปุ่มแชร์เข้า LINE

> สถานะ: ✅ ปุ่มใช้งานได้ (คัดลอก/เปิด LINE) · ⚠️ **หน้าต่างเลือกแชตใช้ไม่ได้ — LINE ตอบ
> `FORBIDDEN` ทั้งที่เงื่อนไขครบทุกข้อ** (สรุปผลการไล่หาสาเหตุอยู่ท้ายหน้า) · หยุดไล่ต่อแล้ว

## ⛔ ข้อสรุป (2026-08-01, v5.88.1) — `shareTargetPicker` ถูกปฏิเสธที่ฝั่ง LINE

ไล่จนครบทุกเงื่อนไขที่ LINE ระบุไว้ วัดค่าจริงบนเครื่องผู้ใช้ด้วย `?liffdebug=1`:

```
sdk=loaded  init=ok  inClient=true  ctx=utou/full
picker=false  perm=granted  pickErr=FORBIDDEN
```

| เงื่อนไข | ผล | หลักฐาน |
|---|---|---|
| เปิดเป็น LIFF launch จริง (ไม่ใช่ in-app browser) | ✅ | `ctx=utou/full` |
| SDK โหลด + `liff.init()` สำเร็จ | ✅ | `sdk=loaded init=ok` |
| CSP ไม่บล็อกอะไร | ✅ | ไม่มีบรรทัด `CSP` |
| scope `chat_message.write` ที่ตัว LIFF app | ✅ | คอนโซล: `openid, chat_message.write` |
| ผู้ใช้กดอนุญาตแล้ว | ✅ | `perm=granted` |
| LINE ยอมให้เรียก | ❌ | `pickErr=FORBIDDEN` |

**สรุป: ไม่ใช่บั๊กของโค้ดเรา** เป็นการปฏิเสธระดับแพลตฟอร์มของ LINE ซึ่งแก้จากฝั่งเราไม่ได้
(สาเหตุที่แท้จริงยังไม่ทราบ — อาจเป็นข้อจำกัดของประเภทบัญชี/แผนการใช้งาน หรือต้องผ่าน
review บางอย่าง · ตรวจสอบเพิ่มได้ที่เอกสาร LINE หรือติดต่อ LINE support)

**สิ่งที่เหลืออยู่และใช้งานได้จริง**: ปุ่มแชร์คัดลอกข้อความให้แล้ววางในแชต (พฤติกรรมเดิมตั้งแต่ต้น
ไม่เคยพัง) · บนเบราว์เซอร์มือถือปกติยังเด้งไป LINE พร้อมข้อความได้

**โค้ดที่ค้างไว้โดยตั้งใจ** — ไม่ต้องลบ ไม่มีผลเสีย และถ้า LINE เปิดให้เมื่อไรจะทำงานเองทันที:
- เรียก `shareTargetPicker` ตรง ๆ ไม่เชื่อ `isApiAvailable` (v5.88.0)
- ขอสิทธิ์ให้ผู้ใช้อัตโนมัติเมื่อสถานะเป็น `prompt` (v5.87.0)
- โหมด `?liffdebug=1` + ฟิลด์ `reason` ใน analytics

**คำแนะนำเรื่อง rich menu**: ในเมื่อหน้าต่างเลือกแชตใช้ไม่ได้ **LIFF URL ไม่มีข้อได้เปรียบ
เหนือลิงก์ธรรมดาอีกต่อไป** (แถมมีขั้นตอน login/ส่งต่อเพิ่ม) → ใช้ลิงก์ `https://rxbenz.github.io/...`
ธรรมดาทั้ง 6 ปุ่มจะเรียบง่ายและเสถียรกว่า

## เดิม vs ใหม่

**เดิม**: กดปุ่ม "แชร์ LINE" = คัดลอกข้อความลง clipboard แล้วบอกให้ผู้ใช้ไปวางใน LINE เอง

**ใหม่**: ไล่จากวิธีที่ดีที่สุดที่ทำได้ในเครื่องนั้น ๆ

| สถานการณ์ | สิ่งที่เกิดขึ้น | analytics `method` |
|---|---|---|
| เปิดหน้าเว็บ**ใน LINE** + LIFF ใช้ได้ | หน้าต่าง **เลือกแชต/กลุ่ม** แล้วส่งเป็นข้อความเลย | `liff_picker` |
| ผู้ใช้กดยกเลิกหน้าต่างเลือกแชต | ไม่ทำอะไรต่อ (ไม่ถือว่าพลาด) | `liff_cancelled` |
| มือถือ เปิดในเบราว์เซอร์ปกติ | เปิด LINE พร้อมข้อความเตรียมไว้ (`line.me/R/share`) | `line_url` |
| เดสก์ท็อป / ทุกกรณีที่เหลือ | คัดลอกลง clipboard (พฤติกรรมเดิม) | `clipboard` |

> **ปุ่มนี้ไม่มีทางตัน** — SDK โหลดไม่ขึ้น, ไม่มีสิทธิ์, ผู้ใช้บล็อก popup, API พัง → ตกมาที่ clipboard เสมอ (ล็อกด้วยเทสต์ `test/share-line.test.js`)

| หน้า | ปุ่มในการ์ดผล |
|---|---|

| `vanco-tdm` | `📋 แชร์ LINE` · `📄 Export PDF` |
| `calculator` | `📋 คัดลอก` · `💬 LINE` ← **เพิ่งเพิ่ม v5.85.0** |

> ⚠️ **แก้บันทึกที่เคยผิด**: เอกสารรุ่นก่อนบอกว่า calculator "มีปุ่มแชร์" ตั้งแต่ Phase 7

> หาปุ่มแชร์ในหน้านี้ไม่เจอ · v5.85.0 เพิ่มปุ่มให้แล้ว ใช้ป้ายชุดเดียวกับ `allergy`

## ต้องทำในคอนโซล (ครั้งเดียว)

เปิดสิทธิ์ให้ LIFF app ส่งข้อความแทนผู้ใช้ได้ ไม่งั้นจะตกมาใช้ clipboard ตลอด

1. https://developers.line.biz/console/ → provider **IV DrugRef** → channel **IV DrugRef LIFF** (LINE Login)
2. แท็บ **LIFF** → คลิก LIFF app (`2010742553-w9T3Wtjt`)
3. **Scopes** → ติ๊กเพิ่ม **`chat_message.write`** (คงของเดิม `openid` ไว้)
4. บันทึก

> ⚠️ LINE เตือนว่าเปิด scope นี้แล้ว **ปุ่มย่อหน้าต่าง (minimize) ของ LIFF จะถูกปิด** — ไม่กระทบเรา เพราะเราไม่ได้ใช้ฟีเจอร์นั้น

## หาสาเหตุเมื่อปุ่มยังตกไปที่ "คัดลอก" — โหมด `?liffdebug=1`

ตกมาที่ clipboard ได้จาก **3 สาเหตุที่ผู้ใช้เห็นเหมือนกันหมด** แต่แก้คนละที่ เติม
`?liffdebug=1` ท้าย URL แล้วกดปุ่ม LINE → toast จะบอกเหตุผลแทนข้อความปกติ เช่น

```
https://liff.line.me/2010742553-w9T3Wtjt/calculator.html?liffdebug=1
```

| toast ที่ได้ | แปลว่า | แก้ที่ |
|---|---|---|
| `sdk=timeout` / `sdk=error` | โหลด LIFF SDK ไม่ขึ้น | เน็ต หรือ CSP `script-src` |
| `... | CSP script-src←https://…` | เบราว์เซอร์บล็อกตาม CSP | เพิ่มโดเมนใน CSP หน้านั้น |
| `init=fail:…` / `init=throw:…` | `liff.init()` พัง (ดูรหัสที่ตามมา) | ตั้งค่า LIFF app |
| `ctx=none` | **ไม่ใช่ LIFF launch จริง** (in-app browser ธรรมดา) | เปิดด้วยลิงก์ `liff.line.me/...` |
| `ctx=utou/full`, `none/full` ฯลฯ | เป็น LIFF launch จริง | — |
| `picker=false perm=prompt` | scope ตั้งไว้แล้ว แต่ **ผู้ใช้ยังไม่ได้กดอนุญาต** | ปุ่มจะขอสิทธิ์ให้เอง (v5.87.0) |
| `picker=false perm=unavailable` | **ไม่มี scope** ที่ตัว LIFF app | เปิด scope `chat_message.write` |
| `picker=false perm=granted` + `pickErr=…` | ครบทุกเงื่อนไข แต่ LINE ปฏิเสธจริง — อ่านรหัสใน `pickErr` | ตามรหัสที่ได้ |

> ⚠️ **`inClient=true` ไม่ได้แปลว่าอยู่ใน LIFF browser** — มันเป็น true ทุกที่ที่อยู่ในแอป LINE
> รวมถึง in-app browser ธรรมดาซึ่ง `shareTargetPicker` **ใช้ไม่ได้ตั้งแต่ต้น** และ LINE จะตอบ
> **`FORBIDDEN`** ซึ่งเป็น**รหัสเดียวกับ**ตอนที่แอปไม่ได้รับอนุญาตจริง ๆ → ต้องดู `ctx` ถึงจะแยกออก
> (`getContext()` คืนค่าเฉพาะตอนเป็น LIFF launch จริง) · v5.88.1

> **`isApiAvailable()` เป็นแค่คำบอกเล่า ไม่ใช่คำตัดสิน** — บนเครื่องจริงเจอ
> `inClient=true perm=granted` ครบทุกเงื่อนไข แต่มันยังตอบ `picker=false`
> ตั้งแต่ **v5.88.0** ปุ่มจะ **เรียกหน้าต่างเลือกแชตไปเลย** ไม่เชื่อค่านี้ ถ้าเรียกไม่ได้จริง
> LINE จะโยน error ออกมา → ตกไปคัดลอก (จุดเดิมกับตอนที่เชื่อค่านี้ ไม่มีอะไรแย่ลง)
> และ **รหัส error ตัวจริงถูกเก็บไว้ที่ `pickErr`** จะได้ไม่ต้องเดาอีก

> **`scope ที่ตั้งในคอนโซล` ≠ `ผู้ใช้อนุญาตแล้ว`** — เป็นคนละอย่างและเป็นกับดักที่เจอจริง:
> คอนโซลแสดง `openid, chat_message.write` ครบ แต่บัญชีที่เคยเปิดแอปนี้ **ก่อน**
> เพิ่ม scope จะถูกจำสิทธิ์ชุดเก่าไว้ และ LINE **ไม่ถามใหม่เอง** → `picker=false` เงียบ ๆ
> ตั้งแต่ v5.87.0 ปุ่มจะเรียก `liff.permission.requestAll()` ให้เองเมื่อสถานะเป็น `prompt`
> แล้วลองเปิดหน้าต่างเลือกแชตอีกครั้ง (ถ้าผู้ใช้ไม่อนุญาต → คัดลอกเหมือนเดิม
> และ **ไม่ถามซ้ำทุกครั้งที่กด** เพราะถามเฉพาะสถานะ `prompt` เท่านั้น)

เหตุผลเดียวกันถูกส่งเข้า analytics เป็นฟิลด์ `reason` (`no_sdk` / `no_picker` /
`no_grant` / `picker_error`) คู่กับ `method` เดิม — ดูย้อนหลังใน dashboard ได้โดยไม่ต้องเปิดโหมด debug

> โหมดนี้ **ไม่เปลี่ยนพฤติกรรมการแชร์เลย** เปลี่ยนแค่ข้อความใน toast · ผู้ใช้ที่ไม่ได้เติม
> พารามิเตอร์จะไม่เห็นอะไรต่างจากเดิม (ล็อกด้วยเทสต์ "no diagnostics leak to real users")

## ข้อจำกัดที่ควรรู้

หน้าต่างเลือกแชต (`shareTargetPicker`) ต้องเปิดหน้าเป็น **LIFF launch** เท่านั้น
(ลิงก์ `liff.line.me/...` · ตรวจได้ที่ `ctx` ในโหมด debug — in-app browser ธรรมดาให้ `ctx=none`)

> ~~ข้อความเดิมตรงนี้แนะนำให้เปลี่ยนปุ่ม rich menu เป็น LIFF URL เพื่อให้ได้หน้าต่างเลือกแชต~~
> **ทดลองแล้วไม่ได้ผล** — เปิดเป็น LIFF launch จริง (`ctx=utou/full`) แล้วยังได้ `FORBIDDEN`
> ดูข้อสรุปด้านบนสุดของหน้านี้ · ปัจจุบัน**แนะนำให้ใช้ลิงก์ธรรมดาทั้ง 6 ปุ่ม** เพราะ LIFF URL
> ไม่ให้ประโยชน์เพิ่มแล้ว แต่เพิ่มขั้นตอน login/ส่งต่อ (และเคยทำให้เกิดจอโหลดวน v5.83.x)
